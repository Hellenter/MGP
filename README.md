# MGP — миниигры в стиле Hypixel (Paper 26.x)

Каркас плагина: хаб с меню → лобби ожидания с голосованием → игра в отдельном мире → итоги → мир удаляется.
Сейчас есть режимы **Голодные игры**, **Билд баттл**, **Прятки** и **Prop Hunt**.

## Сборка
Нужен **JDK 25**, потому что Paper 26.x требует Java 25.
```
./gradlew build          # Windows: gradlew.bat build
```
Готовый jar появится в `build/libs/MGP-0.3.0.jar`. Его нужно положить в `plugins/`.
Версия Paper API задаётся в `build.gradle.kts` (сейчас `26.3.build.+`).

## Как устроены карты
* Шаблоны миров лежат в `plugins/MGP/templates/<имя>/`. Это обычные папки миров.
* На каждую игру шаблон копируется в `mgp_<режим>_g<N>` и загружается без автосохранения. После игры мир выгружается и удаляется, поэтому карта каждый раз «чистая».
* Лобби ожидания устроено так же: отдельный маленький шаблон (`waiting.template` в режиме).
* Если сервер упал, оставшиеся папки `mgp_*` удаляются при следующем старте.

## Импорт готовых карт из большого мира
Если карты уже построены в одном большом мире, их не нужно переносить руками:
```
/mgp import <карта> <режим> <x1> <y1> <z1> <x2> <y2> <z2> [мир] [название]
/mgp import <карта> <режим>        ← область из /mgp setup pos1 и pos2
```
То же самое есть в админ-панели: пункт «Импорт карты из мира».

Что происходит при импорте:
* Плагин копирует **только чанки этой области** (файлы регионов фильтруются побайтно) в `templates/<карта>`. Игры не копируют весь мир.
* Создаётся `maps/<карта>.yml` с режимом, названием, центром, барьером и точкой наблюдателей. Там же записан источник: мир и углы области.
* В области ищутся сундуки: обычный сундук получает tier1, сундук-ловушка tier2. Соответствие меняется в `config.yml` → `import.chest-tiers`.
* Координаты в шаблоне те же, что в исходном мире. Спавны можно ставить прямо в большом мире командой `/mgp setup spawn <карта>`.
* Повторный импорт той же карты пересоздаёт шаблон, а спавны и настройки остаются. Удобно, если поменял карту в мире. В панели для этого есть кнопка «Пересоздать шаблон из мира».
* Режим может ещё не существовать (например, прятки). Карта подхватится, когда появится режим с этим id.

## Первичная настройка
1. Запусти сервер один раз. Создадутся `plugins/MGP/config.yml`, `modes/*.yml` и `maps/*.yml` (примеры).
2. В `config.yml` укажи мир и точку хаба.
3. Зайди в мир готовой карты (например через Multiverse или с другого сервера) и выполни команды:
   * `/mgp setup export hg_forest` скопирует мир в шаблон;
   * `/mgp setup create forest hunger_games hg_forest` создаст `maps/forest.yml`;
   * `/mgp setup spawn forest` нужно повторить на каждом спавне;
   * `/mgp setup chest forest tier2` выполняется, глядя на сундук;
   * `/mgp setup spectator forest`, `/mgp setup center forest 300`, `/mgp setup trader forest default weaponsmith`;
   * для Билд баттла: `/mgp setup pos1`, `/mgp setup pos2`, затем `/mgp setup plot <карта>`, стоя в точке появления участка.
4. Для лобби ожидания сделай `export` в `hg_waiting` и `bb_waiting`, а точку задай через `/mgp setup waiting hunger_games`.
5. Если поменял что-то в мире карты, снова выполни `/mgp setup export <шаблон>`.
6. `/mgp setup info <карта>` проверяет, всё ли на месте.

## Прятки и Prop Hunt
Оба режима — тип `hide_and_seek` (`modes/hide_and_seek.yml` и `modes/prop_hunt.yml`), различаются `settings.variant`.
* Ищущие (1 или доля `seeker-ratio`) первые `hide-time` секунд ослеплены и стоят. Пойманный прячущийся становится ищущим (`caught: seeker`) или наблюдателем (`caught: spectator`).
* Нашли всех — победа ищущих, дожили до конца `time-limit` — победа прячущихся.
* Ники над головами скрыты всем (`hide-nametags: true`): ни через стены, ни вблизи.
* **Prop Hunt:** прячущийся невидим, вместо него блок. Предмет «Маскировка» + ПКМ по блоку — стать этим блоком. Ищущий бьёт подозрительные блоки; удар по обычному блоку стоит здоровья (`miss-penalty`).
* **Таунты** (нотный блок в слоте 9 у прячущихся): звук и частицы из твоего укрытия, дают очки. **Провокации** (рог у ищущих): все прячущиеся выдают себя — звук, частицы, салют или подсветка сквозь стены. Списки `taunts` и `provocations` настраиваются в режиме. Раз в `auto-taunt` секунд прячущиеся сами издают звук.
* Карта: спавны (`/mgp setup spawn`) — где начинают все; `/mgp setup seekerspawn <карта>` — отдельная комната, где ищущие ждут (необязательно).
  `/mgp setup alsomode <карта> prop_hunt` — карта играется и в другом режиме, без копии.

## Скрипты карт (вместо командных блоков)
Интерактивные объекты хранятся в файле карты (`maps/<карта>.yml` → `scripts`) и работают только во время игры, для живых игроков.
```yaml
scripts:
  - id: hatch1
    type: hold              # hold | button | plate | zone
    block: "120 64 -40"     # железный люк, кнопка, плита или центр зоны
    hold: 3                 # hold: сколько держать Shift
    hint: "<yellow>Зажми <gold><bold>SHIFT</bold></gold>, чтобы активировать"
    progress: "<aqua>Телепорт"   # надпись на шкале прогресса
    particle: PORTAL        # частицы вокруг блока (none — без них)
    cooldown: 1             # перезарядка для игрока, сек
    mode: REPEAT            # REPEAT | ONCE (раз за игру) | PER_PLAYER (раз для каждого)
    actions:
      - "teleport: 300 70 50"
      - "sound: minecraft:entity.enderman.teleport"
```
* **hold** — игрок подходит к блоку: над хотбаром подсказка. Держит Shift — боссбар с процентами и оставшимся временем, частицы закручиваются вокруг. Отпустил или отошёл — сброс.
* **button** — ПКМ по блоку (кнопка, рычаг, люк, любой блок). `cancel-use: true` — не открывать/не нажимать сам блок.
* **plate** — наступить на блок. **zone** — войти в радиус `radius` вокруг блока.
* Действия те же, что у триггеров и таймлайна, плюс `teleport: x y z [yaw pitch]`, `particle: <тип> [кол-во] [x y z]`, `setblock: x y z <блок>`.

В игре: смотри на люк и введи `/mgp setup script <карта> hatch1 hold`, затем встань в точку назначения и введи `/mgp setup script <карта> hatch1 tphere`.
Ещё: `action <действие>`, `set <ключ> <значение>`, `clear`, `remove`; `/mgp setup scripts <карта>` — список. В панели — вкладка «Скрипты» у карты.

## Админ-панель (отдельное окно)
Плагин сам поднимает маленький веб-сервер с панелью управления. Никаких дополнительных программ не нужно.

1. В игре выполни `/mgp panel` (нужно право `mgp.admin`) и нажми на ссылку `[открыть]`. В ссылке уже есть ключ доступа.
   Ключ также лежит в `config.yml` → `panel.token`.
2. Чтобы панель открывалась отдельным окном, нажми в ней кнопку «Открыть в отдельном окне».
   Или установи её как приложение: в Chrome/Edge значок «Установить» в адресной строке. После этого панель живёт в своём окне с иконкой на рабочем столе.

Что можно делать в панели:
* смотреть онлайн, TPS и активные игры, принудительно стартовать или закрывать игры;
* настраивать режимы через формы: игроки и таймеры, голосования, модификаторы, киты, тиры сундуков, торговцы, события по времени, инфо-панель (с предпросмотром цветов), настройки режима;
* настраивать карты: спавны, сундуки, торговцы, триггеры, участки;
* менять общие настройки (хаб, голосование WEIGHTED, сама панель);
* редактировать любой файл целиком на вкладке YAML.

Перед сохранением плагин проверяет конфиг. Если в нём ошибка, файл не сохранится, а панель покажет причину. Сохранённые настройки сразу применяются к новым играм, текущие игры доигрывают со старыми.
Сохранение через формы убирает комментарии внутри разделов. Если комментарии важны, правь файл на вкладке YAML: там он сохраняется как есть.

**Сервер на хостинге.** По умолчанию панель слушает только `127.0.0.1:8765`, то есть доступна лишь с той же машины. Варианты:
* SSH-туннель (самый безопасный): `ssh -L 8765:127.0.0.1:8765 user@сервер`, потом открыть `http://localhost:8765`;
* или `panel.host: 0.0.0.0` плюс открытый порт и `panel.public-url: http://IP:8765`. Тогда ключ — единственная защита, никому не показывай ссылку.

## Команды
| Команда | Что делает |
|---|---|
| `/play [режим]` | меню игр или быстрый вход |
| `/leave` (`/hub`, `/l`) | выйти в хаб |
| `/mgp start` | принудительный старт (в лобби ожидания) |
| `/mgp list` | активные сессии |
| `/mgp reload` | перечитать конфиги |
| `/mgp panel` | ссылка на админ-панель |
| `/mgp setup` | команды настройки карт |

Право `mgp.admin` нужно для настройки и принудительного старта. Права на киты задаются полем `permission` у кита.

## Что настраивается в `modes/<режим>.yml`
* `min-players`, `max-players`, `countdown`, `fast-countdown` (ускоренный старт при полном лобби), `time-limit`, `max-sessions`.
* `map-vote.type` выбирает тип голосования:
  * `MOST_VOTES`: побеждает вариант с наибольшим числом голосов;
  * `RANDOM_VOTED`: случайный вариант среди тех, за которые голосовали;
  * `WEIGHTED`: каждый голос добавляет шанс (параметры в `config.yml`);
  * `NONE`: случайная карта без голосования.
* `modifiers` задаёт группы модификаторов (время суток, погода, здоровье, эффекты). Режим выбора для каждой группы: `VOTE`, `RANDOM`, `FIXED` или `OFF`.
* `kits`, `default-kit` и `start-items` задают наборы и стартовые предметы.
* `loot` содержит тиры сундуков, `trades` — наборы сделок для торговцев.
* `timeline` — события по времени (пополнение сундуков, сужение барьера, дезматч...).
* `sidebar` задаёт строки инфо-панели справа для каждой фазы, с плейсхолдерами `{time}`, `{alive}`, `{kills}` и другими.
* `settings` — параметры конкретного режима.

### Действия (для timeline, триггеров, модификаторов, китов, win-actions)
`message:`, `broadcast:`, `title: верх | низ`, `actionbar:`, `sound: minecraft:...`, `time: 18000 lock`,
`weather: clear|rain|thunder`, `gamerule: <id> <значение>`, `effect: speed 1 [сек]`, `clear-effects`,
`give: ARROW 16`, `heal`, `max-health: 40`, `border: <размер> [сек]`, `refill-chests [tier]`,
`command: <консольная команда с {player}>`, `mode: deathmatch | pvp-on | pvp-off`.

### Триггеры на карте
Область (`min`/`max`) и режим срабатывания `ONCE`, `PER_PLAYER` или `REPEAT` (каждую секунду, пока игрок внутри).

## Структура кода
```
ru.mgp
├─ MGPPlugin              — точка входа
├─ world/WorldService     — копирование шаблонов, загрузка/выгрузка/удаление миров
├─ config/                — ModeConfig, MapConfig, киты, лут, сделки, модификаторы, таймлайн
├─ vote/                  — голосования и 4 типа подсчёта
├─ session/
│  ├─ GameSession         — состояние одной игры (ожидание → отсчёт → игра → итоги)
│  ├─ SessionManager      — очередь: подбор/создание сессии, общий таймер
│  ├─ ActionRunner        — универсальные действия
│  ├─ HubService          — хаб
│  └─ VisibilityService   — изоляция: видишь и слышишь только свою сессию
├─ logic/                 — режимы: GameLogic (база), HungerGamesLogic, BuildBattleLogic
├─ ui/                    — инфо-панель, GUI-меню, предметы хотбара
├─ panel/                 — веб-сервер и API админ-панели (интерфейс: resources/web)
├─ listener/              — события
└─ command/MgpCommand     — команды и /mgp setup
```

### Как добавить новый режим
1. Создай класс `extends GameLogic` и реализуй `onStart()` и нужные события.
2. Зарегистрируй его в `GameLogics.create(...)` под своим `type`.
3. Создай `modes/<режим>.yml` с этим `type`.
