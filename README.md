# MGP — миниигры в стиле Hypixel (Paper 26.x)

Каркас плагина: хаб с меню → лобби ожидания с голосованием → игра в отдельном мире → итоги → мир удаляется.
Сейчас есть режимы **Голодные игры**, **Билд баттл**, **Прятки**, **Prop Hunt**, **Осада** и **Штурм**.

## Сборка
Нужен **JDK 25**, потому что Paper 26.x требует Java 25.
```
./gradlew build          # Windows: gradlew.bat build
```
Готовый jar появится в `build/libs/MGP-0.3.0.jar`. Его нужно положить в `plugins/`.
Версия Paper API задаётся в `build.gradle.kts` (сейчас `26.3.build.+`).

## Как устроены карты
* Шаблоны миров лежат в `plugins/MGP/templates/<имя>/`. Это обычные папки миров.
* На каждую игру шаблон копируется в `mgp_<режим>_g<N>` и загружается без автосохранения. После игры мир выгружается и удаляется, поэтому карта каждый раз «чистая».
* Лобби ожидания устроено так же: отдельный маленький шаблон (`waiting.template` в режиме).
* Если сервер упал, оставшиеся папки `mgp_*` удаляются при следующем старте.

## Импорт готовых карт из большого мира
Если карты уже построены в одном большом мире, их не нужно переносить руками:
```
/mgp import <карта> <режим> <x1> <y1> <z1> <x2> <y2> <z2> [мир] [название]
/mgp import <карта> <режим>        ← область из /mgp setup pos1 и pos2
```
То же самое есть в админ-панели: пункт «Импорт карты из мира».

Что происходит при импорте:
* Плагин копирует **только чанки этой области** (файлы регионов фильтруются побайтно) в `templates/<карта>`. Игры не копируют весь мир.
* Создаётся `maps/<карта>.yml` с режимом, названием, центром, барьером и точкой наблюдателей. Там же записан источник: мир и углы области.
* В области ищутся сундуки (только для режимов с лутом). Тир задаёт предмет-маркер внутри контейнера: только железный слиток — tier1, только золотой — tier2 (см. «Сундуки и лут» ниже). Если маркеров на карте нет, тир берётся по типу блока: обычный сундук tier1, сундук-ловушка tier2 (`config.yml` → `import.chest-tiers`).
* Координаты в шаблоне те же, что в исходном мире. Спавны можно ставить прямо в большом мире командой `/mgp setup spawn <карта>`.
* Повторный импорт той же карты пересоздаёт шаблон, а спавны и настройки остаются. Удобно, если поменял карту в мире. В панели для этого есть кнопка «Пересоздать шаблон из мира».
* Режим может ещё не существовать (например, прятки). Карта подхватится, когда появится режим с этим id.

## Первичная настройка
1. Запусти сервер один раз. Создадутся `plugins/MGP/config.yml`, `modes/*.yml` и `maps/*.yml` (примеры).
2. В `config.yml` укажи мир и точку хаба.
3. Зайди в мир готовой карты (например через Multiverse или с другого сервера) и выполни команды:
   * `/mgp setup export hg_forest` скопирует мир в шаблон;
   * `/mgp setup create forest hunger_games hg_forest` создаст `maps/forest.yml`;
   * `/mgp setup spawn forest` нужно повторить на каждом спавне;
   * `/mgp setup chest forest tier2` выполняется, глядя на сундук;
   * `/mgp setup spectator forest`, `/mgp setup center forest 300`, `/mgp setup trader forest default weaponsmith`;
   * для Билд баттла: `/mgp setup pos1`, `/mgp setup pos2`, затем `/mgp setup plot <карта>`, стоя в точке появления участка. Так для каждого участка, потом `/mgp setup wall <карта> auto` — стены между участками (или выделить стену и `/mgp setup wall <карта>`), `/mgp setup arena <карта>` — центр арены, `/mgp setup show <карта>` — проверить частицами, `/mgp setup plots <карта>` — список.
4. Для лобби ожидания сделай `export` в `hg_waiting` и `bb_waiting`, а точку задай через `/mgp setup waiting hunger_games`.
5. Если поменял что-то в мире карты, снова выполни `/mgp setup export <шаблон>`.
6. `/mgp setup info <карта>` проверяет, всё ли на месте.

## Выделение областей
* `/mgp setup wand` — золотой топор выделения, как //wand у WorldEdit: ЛКМ по блоку — pos1, ПКМ по блоку — pos2. Блоки им не ломаются, с деревянным топором WorldEdit и палочкой скриптов (`/mgp wand`) не путается.
* Или `/mgp setup pos1` / `pos2` там, где стоишь; дальше `expand`, `contract`, `shift`, меню граней `/mgp setup sel`.

## Play-зона карты
* `/mgp setup zone <карта>` — область из выделения (`pos1`/`pos2`, удобно `/mgp setup expand 20 vert`), за которую игроки не выйдут. Областей может быть несколько. У края видна аккуратная сетка частиц (только тому, кто рядом).
* Граница — барьер: пройти за неё нельзя, никого никуда не телепортирует. Кого отбросило наружу, может идти только обратно к зоне. Запас за краем — `settings.zone-margin` режима (по умолчанию 0 блоков). Эндер-жемчуг за границу не летит.
* `/mgp setup teamzone <карта> <команда>` — стартовая зона команды (в осаде `attackers` / `defenders`, в прятках `seeker` / `hider`). `/mgp setup teamzone <карта> open <сек>` — через сколько секунд граница между командами снимается (по умолчанию из режима `team-zones-open`; в осаде граница открывается в конце подготовки `prep-time`). Действие `zones: open` / `zones: close` — снять или вернуть границу из триггера или timeline.
* `/mgp setup show <карта>` подсвечивает play-зону голубым, зоны команд оранжевым и синим; `/mgp setup info <карта>` предупредит, если спавн оказался за зоной.

## Билд баттл
* Каждому игроку свой участок, между участками стены. Время стройки вышло — стены исчезают, все переносятся в центр арены (`arena`, иначе `spectator`) и `reveal-time` секунд смотрят на все постройки.
* Потом всех по очереди переносит на каждый участок: оценка блоками в хотбаре от красного к зелёному (`grades`), ПКМ — поставить, можно передумать, пока идёт время. Чья постройка — не говорится; свою оценивать нельзя.
* В конце — места и очки в чате, а над каждой постройкой табличка с ником автора и очками.
* Со своего участка не уйти дальше `plot-margin` блоков (по умолчанию 5): у края останавливает, как барьер, никуда не телепортирует. Время суток всегда полдень (`time: 6000` в режиме, голосования за время нет).

## Прятки и Prop Hunt
Оба режима — тип `hide_and_seek` (`modes/hide_and_seek.yml` и `modes/prop_hunt.yml`), различаются `settings.variant`.
* Ищущие (1 или доля `seeker-ratio`) первые `hide-time` секунд ослеплены и стоят. Пойманный прячущийся становится ищущим (`caught: seeker`) или наблюдателем (`caught: spectator`).
* Нашли всех — победа ищущих, дожили до конца `time-limit` — победа прячущихся.
* Ники над головами скрыты всем (`hide-nametags: true`): ни через стены, ни вблизи.
* **Prop Hunt:** прячущийся невидим, вместо него блок. Предмет «Маскировка» + ПКМ по блоку — стать этим блоком. Ищущий бьёт подозрительные блоки; удар по обычному блоку стоит здоровья (`miss-penalty`).
* **Таунты** (нотный блок в слоте 9 у прячущихся): звук и частицы из твоего укрытия, дают очки. **Провокации** ищущих — отдельные предметы в хотбаре (`provocation-items: true`, иначе одно меню через рог): прячущиеся выдают себя звуком, частицами, салютом или подсветкой сквозь стены. У провокации есть `target: nearest` (только ближайший прячущийся) и условия `max-hiders` (прячущихся осталось не больше N) и `max-time-left` (до конца не больше N сек.). Списки `taunts` и `provocations` настраиваются в режиме. Раз в `auto-taunt` секунд прячущиеся сами издают звук.
* **Баланс пряток:** нож ищущего наносит `seeker-damage` HP за полный удар (9, без критов; при 0 — ловит с `hits-to-kill` полных ударов), таунт лечит прячущегося на `taunt-heal` HP (2) и доступен не чаще раза в `taunt-cooldown` секунд (40), ищущий быстрее на `seeker-speed` процентов (5), ищущий не получает урона ни от чего. `disable-hunger` — голод не тратится, `no-regen` — здоровье само не восстанавливается.
* **Прятки и Prop Hunt — два отдельных режима** (`hide_and_seek` и `prop_hunt`): у каждого свой пункт в меню игр и свои карты. Карту назначают командой `/mgp setup modes <карта>` — меню, где клик включает режим для карты, Shift+клик делает его основным. Или сразу: `/mgp setup modes <карта> prop_hunt` (только Prop Hunt), `/mgp setup modes <карта> hide_and_seek prop_hunt` (обе). Какие карты где — `/mgp setup maps`.
* Карта: спавны (`/mgp setup spawn`) — где начинают все; `/mgp setup seekerspawn <карта>` — отдельная комната, где ищущие ждут (необязательно).
  `/mgp setup alsomode <карта> prop_hunt` — карта играется и в другом режиме, без копии.

## Выделение как в WorldEdit
Углы задаются `/mgp setup pos1` и `pos2`, рамка видна сразу. Дальше её можно править, не переставляя углы:
* `/mgp setup expand <n> [обратно] [направление]` — как `//expand`; `expand vert` — на всю высоту мира. Направление: `me` (куда смотришь, по умолчанию), `back`, `left`, `right`, `up`, `down`, `north`, `south`, `east`, `west` (или `x+ x- y+ y- z+ z-`).
* `contract`, `shift <n> [направление]`, `outset` / `inset <n> [-h|-v]` — как в WorldEdit.
* **Параллелепипед по граням.** `/mgp setup sel` — меню из шести граней: ЛКМ двигает грань наружу, ПКМ внутрь, Shift — по 10, Q — грань туда, где ты стоишь. Командой: `/mgp setup face <грань> <координата | +n | -n | here>` (отрицательная координата через `=`: `face north =-120`).
* `/mgp setup box x1 y1 z1 x2 y2 z2` — весь параллелепипед сразу (`~` — твоя координата), `/mgp setup size` — размер.

## Спавны команд и динамические спавны
Кроме обычного списка `spawns` у карты могут быть спавны для команд и групп (`spawn-points`):
```yaml
spawn-points:
  - {pos: "10 70 10", team: seeker}                       # только для ищущих
  - {pos: "20 70 20", team: hider}                        # только для прячущихся
  - {pos: "30 70 30", team: attackers, group: stage2, enabled: false}  # закрыт до действия
```
* `/mgp setup teamspawn <карта> <команда|all> [группа] [locked]` — добавить спавн там, где стоишь. `locked` — закрыт, пока его не откроют.
* В прятках прячущиеся встают на спавны `hider`, ищущие — на `seeker` (или в комнату `seeker-spawn`, если она задана). Если командных спавнов нет, берутся обычные.
* Действие `spawns: enable <группа>` (или `disable`) открывает группу — из триггера, скрипта, таймлайна или цели. Открытые позже группы важнее (`priority`), так что игроки сразу начинают появляться на новом рубеже.
* `/mgp setup spawns <карта>` показывает все спавны с кнопкой телепорта.

## Осада (Siege)
Режим `modes/siege.yml` (тип `siege`): защитники держат крепость, атакующие должны убить их всех. Хоть один защитник жив к концу боя — победа защитников.
* **Команды:** до 8 игроков, роли раздаются только при старте по `defender-ratio` (0.75: 6 защиты и 2 атаки при 8), пати всегда за одну сторону.
* **Время:** подготовка `prep-time` (граница между `teamzone` команд закрыта, PvP и ТНТ нет), затем бой `fight-time`. За `defender-glow` до конца защитники светятся. `time-limit` режима не используется.
* **Наборы:** выбираются только после старта, у каждой команды свои (`kits` с `team: defenders|attackers`; наборы без `team` — общие, если у команды нет своих). Одинаковых в команде — не больше `max-same-kit` (2); за `kit-select-time` сек. не выбрал — выдаётся наименее занятый.
* **Ники:** противников не видно (`hide-enemy-nametags`), союзников видно.
* **Карта:** выдели крепость pos1/pos2 и введи `/mgp setup fortress <карта>` (можно несколько областей). Спавны: `/mgp setup teamspawn <карта> defenders` и `... attackers`.
* **Блоки:** руками ломаются только `breakable-blocks` (земля, доски, шерсть...) и то, что поставлено за игру. Стены — только ТНТ: он поджигается сразу при установке и ломает всё, кроме `explosion-proof`. Блоки от взрыва не выпадают.
* **Починка:** у защитников молот (`repair.item`, по умолчанию кисть). ПКМ по стене возвращает исходные блоки рядом (`radius`, `blocks-per-use`, `cooldown`), игроков не замуровывает. Целостность крепости — на шкале сверху и в `{integrity}`.
* **Ресурсы:** `defender-items` / `attacker-items`, у атакующих есть ТНТ. Атакующий возрождается через `attacker-respawn` сек. и не теряет вещи (новый ТНТ не выдаётся), защитник выбывает.
* **Способности** (`abilities`): предмет, ПКМ — действия с перезарядкой. В примере: рывок (`velocity`), ярость (сила и скорость), дымовая шашка (`nearby-effect: 5 blindness` по противникам рядом).
* Действия `mode: attackers-win` / `mode: defenders-win` можно повесить на цель или триггер.

В **голодных играх** столы зачарования работают без лазурита (`free-lapis`), за убийство даётся 2 уровня (`kill-levels`). Уровни сбрасываются в конце игры и при выходе.

## Штурм (Assault)
Режим `modes/assault.yml` (тип `assault`) — большая осада по стадиям. Атакующие разрушают цели на стороне защитников, на каждую стадию своё время (по умолчанию 15:00). Разрушили нужные цели стадии — начинается следующая, спавны обеих команд переезжают дальше. Время стадии вышло — победа защиты. Взята последняя стадия — победа атаки.
* **Команды:** делятся при старте по `defender-ratio` (0.5 — поровну), пати всегда вместе. Ники противников скрыты (`hide-enemy-nametags`).
* **Подготовка** `prep-time` (1:00): все в лимбо, закупаются; граница команд закрыта, PvP и взрывов нет. Потом стадия 1.
* **Цели:** обычные `objectives` карты. Цель ломается взрывами атакующих (ТНТ ставится и сразу поджигается, разрывные стрелы включены). Руками — только если `objective-hand-break: true`. Цели будущих стадий неуязвимы, взрывы защитников цели не задевают, заделывать цель блоками защите нельзя (`defenders-repair`). Остальные блоки — как в осаде: руками только `breakable-blocks` и поставленные за игру.
* **Экономика** (`settings.economy`): у каждого счёт, в начале `start` (800). Монеты: `kill` за убийство (100), `defense-kill` защитнику сверху, если убитый или он сам ближе `defense-radius` к цели стадии (75), `objective` каждому, кто ломал разрушенную цель (400), `objective-team` всей атаке за цель (200), `stage-attackers` / `stage-defenders` за смену стадии (300), `income` раз в `income-every` сек. (50/60). `max` — потолок счёта. Счёт — в инфо-панели (`{money}`) и над хотбаром в лимбо.
* **Лимбо:** после смерти игрок появляется в лимбо своей команды. Там неуязвим, ломать и ставить блоки нельзя, play-зона его не держит. Изумруд в хотбаре — магазин команды (`settings.shop`), можно поставить и продавцов. Выйти можно через `respawn-delay` сек. (5) — пройти в выход (триггер с `mode: deploy`), игрок попадает на текущий спавн команды с защитой `spawn-protection` сек. Нет выхода на карте — в лимбо появляется кнопка «В бой». Нет лимбо — возрождение сразу на спавне.
* **Снаряжение:** после смерти покупки теряются (`keep-inventory: false`) и не выпадают (`drop-items: false`), бесплатный набор выдаётся заново: первый набор команды из `kits` (с `team`) или `defender-items` / `attacker-items`, плюс `start-items`. Цветная куртка показывает команду; купленный нагрудник её заменяет.
* **Магазины:** `shops/assault_attackers.yml` и `shops/assault_defenders.yml` — товары за монеты (`price: "MONEY 300"`) и наборы (см. «Магазины»). Один магазин на обе команды: `shop: <id>`.
* **Смена стадии:** действия стадии (`actions`, например `setblock` — открыть ворота, `zones: open`). `redeploy-on-stage: none | defenders | attackers | all` — перенести живых на новые спавны.
* Действия режима для триггеров и целей: `mode: deploy` (выйти из лимбо), `mode: shop`, `mode: money <n>`, `mode: next-stage`, `mode: attackers-win`, `mode: defenders-win`.
* Плейсхолдеры: `{team} {money} {stage} {stage_name} {phase} {time} {objectives} {objectives_progress} {attackers} {defenders} {limbo}`.

**Как сделать карту штурма** (стой в мире карты):
1. Импорт и play-зона — как обычно (`/mgp import`, `/mgp setup zone`). Стартовые зоны команд (`/mgp setup teamzone`) держат команды порознь в подготовку.
2. Цели: выдели постройку pos1/pos2 → `/mgp setup objective <карта> gate1 60 Ворота` (60% блоков разрушить). Повтори для всех целей.
3. Стадии: `/mgp setup assault <карта> stage 1 15:00 Ворота` → `... stage 1 objective gate1` (ещё цель — ещё раз; `-gate1` — убрать). `... stage 1 require 1` — достаточно одной цели из нескольких (по умолчанию все).
4. Спавны стадий: встань на точку → `/mgp setup assault <карта> stage 1 spawn attackers`, и `... defenders`. Спавнов можно несколько. Пока у стадии нет своих спавнов, берутся спавны прошлой стадии.
5. Лимбо: построй две закрытые комнаты, встань в каждую → `/mgp setup assault <карта> limbo attackers` / `limbo defenders`. Выход: выдели проход pos1/pos2 → `/mgp setup assault <карта> exit` (можно один выход на обе комнаты — разным выделением с разными именами: `exit att_exit`, `exit def_exit`). Продавца в лимбо — через `/mgp shop <id>` → «Поставить продавца здесь».
6. Проверка: `/mgp setup assault <карта> info` — стадии, цели (красные — нет такой цели), сколько спавнов у каждой команды, лимбо и выход.
```yaml
limbo:
  attackers: "100.5 80 200.5 90 0"
  defenders: "-100.5 80 200.5 -90 0"
stages:
  - name: "<yellow>Ворота"
    time: "15:00"
    objectives: [gate1, gate2]
    require: all            # all или число
    spawn-group: stage1     # спавны стадии: spawn-points с этой group
    actions: []             # при начале стадии
  - name: "<gold>Склад"
    time: "15:00"
    objectives: [depot]
    spawn-group: stage2
triggers:
  - {name: limbo_exit, min: "95 79 205", max: "97 82 206", mode: REPEAT, actions: ["mode: deploy"]}
```
Без `stages` вся карта — одна стадия со всеми целями.

## Разрывные стрелы
Стрела с меткой взрывается при попадании в блок, игрока или моба — из лука, арбалета (и мультивыстрела) или раздатчика. Срабатывает **только в режимах**, где включено `settings.explosive-arrows.enabled: true` и только во время игры (в осаде — не в подготовку); в остальных это обычная стрела.
* **Где взять:** `/mgp arrow [кол-во] [тип]` выдаёт стрелы себе — дальше `/mgp kit save`. В наборах, `start-items`, луте и магазинах: `"EXPLOSIVE_ARROW 16"` или `{material: ARROW, amount: 16, explosive: true}` (или `explosive: heavy` — свой тип). Имя, описание и свечение ставятся сами, если не заданы.
* **Настройка в `modes/<режим>.yml`:**
```yaml
settings:
  explosive-arrows:
    enabled: true
    power: 2.0              # сила взрыва (ТНТ = 4, крипер = 3)
    fire: false             # поджигать блоки вокруг (огонь на картах MGP не распространяется)
    break-blocks: true      # ломать блоки
    drop-blocks: false      # выпадают ли сломанные блоки
    protected-blocks: [BEDROCK, BARRIER]   # что взрыв не ломает (можно #теги)
    damage: 1.0             # множитель урона по противникам
    self-damage: 0.5        # по стрелку (0 — не ранит себя)
    team-damage: 0.0        # по союзникам (0 — не ранит своих)
    mob-damage: 1.0         # по мобам
    max-damage: 0           # предел урона за взрыв (20 = 10 сердец), 0 — без предела
    knockback: 1.0          # множитель отбрасывания (0 — без отбрасывания)
    on-players: true        # взрываться при попадании в игрока
    on-entities: true       # в мобов и прочих существ
    on-blocks: true         # в блоки
    trail: true             # дымный след в полёте
    types:                  # свои типы стрел: что не указано — берётся сверху
      heavy: {power: 3.5, fire: true}
```
При попадании в игрока сначала проходит урон самой стрелы, затем взрыв. Убийство взрывом засчитывается стрелку.

## Огнестрельное оружие (`guns.yml`)
Своё оружие MGP с моделями и звуками из ресурспака [QualityArmory](https://github.com/ZombieStriker/QualityArmory-Resourcepack)
(авторы моделей: Zombie_Striker, Hunajameloni). Сам плагин QualityArmory не нужен. Пак берётся по ссылке с их GitHub
без изменений и отправляется игроку, когда он заходит в лобби режима из `resource-pack.modes` (по умолчанию `assault`),
а при возврате в хаб снимается. Кто отказался от пака, видит оружие как арбалет и слышит ванильные звуки
(`required: true` — таких выкидывает из игры в хаб).

Управление:
* **ПКМ** — выстрел. В автоматическом режиме держи ПКМ — идёт очередь (приседать не нужно).
* **F** — сменить режим огня: одиночный / очередь / отсечка (если у оружия их несколько).
* **Q** — перезарядка. Пустой магазин перезаряжается сам при попытке выстрела. Дробовики заряжаются по патрону, выстрел прерывает зарядку.
* **Присед** — прицеливание: меньше разброс и отдача; у СВД и AWP ещё и приближение.

Магазин и режим хранятся у каждого экземпляра оружия; патроны — отдельные предметы в инвентаре (`AMMO rifle 30`).
Пули — мгновенный луч: урон по `damage`, в голову × `headshot`, сквозь союзников пролетают, урон проходит через обычные правила режима
(свои не ранят, в подготовке и в лимбо урона нет). Гранатомёт **M79** стреляет разрывной стрелой из инвентаря
(`EXPLOSIVE_ARROW`): взрыв по её типу из `settings.explosive-arrows` режима. **РПГ-7** стреляет ракетой ПГ-7В (`AMMO rpg 1`),
она летит прямо, без падения, и взрывается по типу `explosive-arrows.types.rpg`.

Патронов три вида: пистолетные (`pistol`), промежуточные (`intermediate`) и винтовочные (`rifle`), плюс картечь (`shotgun`) и ракеты (`rpg`).
Статы взяты из реальных ТТХ: ёмкость магазина, темп стрельбы, время перезарядки и дальность. Урон пропорционален энергии пули, в голову ×4,
после `effective-range` урон падает до `min-damage` на `range`. Kar98k и SPAS-12 заряжаются по патрону.

В магазинах и наборах: `"GUN ak47"`, `"AMMO intermediate 30"` или `{ gun: ak47 }`, `{ ammo: intermediate, amount: 30 }`.
Команды: `/mgp gun list`, `/mgp gun give <оружие> [игрок]`, `/mgp gun ammo <тип> [кол-во] [игрок]`.
Стрелять можно только в идущей игре (админам ещё и в креативе вне игр). Параметры каждого оружия описаны в начале `guns.yml`.

## Цели на разрушение (`objectives`)
Для режимов вроде штурма: выдели постройку (`pos1`/`pos2`) и введи `/mgp setup objective <карта> bunker 60 Бункер`. Когда разрушено 60% её твёрдых блоков (сломаны, взорваны, сгорели), выполняются действия цели: `/mgp setup objective <карта> bunker action spawns: enable stage2`. Пока цель не выполнена, у игроков шкала «Бункер 34% / 60%». Список: `/mgp setup objectives <карта>`. Блоки должны разрешаться ломать в самом режиме.

## Скрипты карт (вместо командных блоков)
Интерактивные объекты хранятся в файле карты (`maps/<карта>.yml` → `scripts`) и работают только во время игры, для живых игроков.
```yaml
scripts:
  - id: hatch1
    type: hold              # hold | button | plate | zone
    block: "120 64 -40"     # железный люк, кнопка, плита или центр зоны
    hold: 3                 # hold: сколько держать Shift
    hint: "<yellow>Зажми <gold><bold>SHIFT</bold></gold>, чтобы активировать"
    progress: "<aqua>Телепорт"   # надпись на шкале прогресса
    particle: PORTAL        # частицы вокруг блока (none — без них)
    cooldown: 1             # перезарядка для игрока, сек
    mode: REPEAT            # REPEAT | ONCE (раз за игру) | PER_PLAYER (раз для каждого)
    actions:
      - "teleport: 300 70 50"
      - "sound: minecraft:entity.enderman.teleport"
```
* **hold** — игрок подходит к блоку: над хотбаром подсказка. Держит Shift — боссбар с процентами и оставшимся временем, частицы закручиваются вокруг. Отпустил или отошёл — сброс.
* **button** — ПКМ по блоку (кнопка, рычаг, люк, любой блок). `cancel-use: true` — не открывать/не нажимать сам блок.
* **plate** — наступить на блок. **zone** — войти в радиус `radius` вокруг блока.
* Действия те же, что у триггеров и таймлайна, плюс `teleport: x y z [yaw pitch]`, `particle: <тип> [кол-во] [x y z]`, `setblock: x y z <блок>`.

В игре: смотри на люк и введи `/mgp setup script <карта> hatch1 hold`, затем встань в точку назначения и введи `/mgp setup script <карта> hatch1 tphere`.
Ещё: `action <действие>`, `set <ключ> <значение>`, `clear`, `remove`; `/mgp setup scripts <карта>` — список. В панели — вкладка «Скрипты» у карты.

### Палочка скриптов (`/mgp wand`)
Скрипты удобнее делать прямо в мире, как в WorldEdit:
1. `/mgp wand` — выдаёт огненный стержень. Пока он в руке, все скрипты карты подсвечены контуром, над ними подписи, точки телепорта видны как площадки.
2. **ЛКМ по блоку** (например, по железному люку) — блок выделяется и открывается выбор типа: удержание Shift, кнопка, плита или зона. Подходящий тип подсказан по блоку.
3. В редакторе: тип, длительность удержания, радиус, перезарядка, режим, частицы, подсказки. Внизу — **«+ Действие»**: телепорт, сообщение, титр, звук (ПКМ — прослушать), эффект, частицы, выдать предмет, поставить блок, лечение, пауза, команда.
4. Для телепорта и «поставить блок» палочка переходит в режим выбора точки: **ЛКМ по блоку** — игрок встанет *на* этот блок (на верх коллизии: плиты, ступеньки, ковры), смотря туда же, куда ты; **ПКМ** — твоя текущая позиция; **Shift+ПКМ** — отмена.
5. **ПКМ** палочкой — список скриптов карты. В редакторе «Проверить» запускает действия на тебе.

Карта определяется сама: по миру игры, по области `source`, в которой ты стоишь, или задаётся явно: `/mgp wand <карта>`. Всё сохраняется в `maps/<карта>.yml`.

## Магазины (`/mgp shop`)
Магазин в стиле Bed Wars: жителя-продавца кликают ПКМ, вверху категории, ниже товары с ценой в железе/золоте/алмазах/изумрудах или любом своём предмете. Готовый пример — `shops/bedwars.yml`.
* `/mgp shop` — все магазины и «+ Новый магазин». `/mgp shop <id>` — редактор.
* В редакторе **кликни по предмету в своём инвентаре** — он станет товаром в выбранной категории. ЛКМ по товару — цена, валюта, количество. Shift+ЛКМ — сдвинуть, Shift+ПКМ — убрать. ПКМ по категории — переименовать, иконка, порядок.
* «Поставить продавца здесь» — записывает жителя в карту (`traders` с полем `shop`), он появляется в каждой игре. «Продавцы на карте» — список с телепортом и удалением.
* Купленная броня сразу надевается, щит — во вторую руку. Админ вне игры: ПКМ по продавцу — магазин, Shift+ПКМ — редактор.
* **Монеты счёта:** `price: "MONEY 300"` — платить монетами, которые игрок зарабатывает в режиме с экономикой (Штурм). В редакторе товара — кнопка «Монеты счёта».
* **Наборы (киты):** несколько предметов за одну покупку. В редакторе: сложи всё в инвентарь (броню надень) → «+ Набор из инвентаря» → название → цена. В файле:
```yaml
- name: "<gold>Штурмовик"
  icon: IRON_AXE
  items: [{material: IRON_AXE, unbreakable: true}, {material: IRON_CHESTPLATE, unbreakable: true}, "TNT 3"]
  price: "MONEY 900"
```

## Друзья (`/f`)
Как на Hypixel: `/f <ник>` (или `/f add <ник>`) отправляет запрос, его принимают кнопкой в чате или `/f accept`. Дружба взаимная и хранится в `plugins/MGP/friends.yml`.
* В **меню пати** друзья в сети стоят первыми (★ Друг): ЛКМ по голове — приглашение в пати. Остальным игрокам там же ПКМ — запрос в друзья. Друзья не в сети показаны в конце серыми.
* `/f` — меню друзей: ЛКМ пригласить, Shift+ПКМ удалить, входящие запросы снизу. `/f list` — список в чат с кнопкой «В пати».
* Друзьям приходит сообщение, когда ты заходишь и выходишь (`friends.join-messages` в config.yml).

## NPC (`/mgp npc`)
* `/mgp npc create <id>` ставит NPC на твоё место в этом мире (хаб и т.п.). `/mgp npc create <id> <карта>` — NPC карты: встань в мире, откуда взята карта; в играх на этой карте он появится в той же точке, а в мире-источнике его видят только админы.
* Настройка — **Shift+ПКМ** по NPC (или `/mgp npc edit <id>`): вид (MANNEQUIN — человек со скином любого игрока по нику, или любой моб), имя, подпись под именем с `{players:<режим>}` и `{online}`, поворот головы к игрокам, «переставить сюда», действия по клику.
* Действия: `join: <режим>` — в очередь режима (с пати, как через меню), `menu` — меню игр, `server: <id>` — на другой сервер сети, `leave` — выйти в хаб, `player-command: <команда>`, `message:`, `title:`, `sound:`, `command:` (от консоли, `{player}` — ник), `teleport:`, `wait: <сек>`. NPC карты в игре понимают все действия скриптов (`give:`, `effect:`, `mode:`...).
* Всё хранится в `plugins/MGP/npcs.yml`. `/mgp npc list|tp|delete`.

## Сущности на картах
При импорте (`/mgp import`) вместе с блоками переносятся сущности: жители со сделками, вагонетки (с содержимым), стойки для брони, рамки с предметами, картины. Если карта была импортирована до 0.6.0, импортируй её заново — раньше сущности из последнего чанка файла терялись.
Жители плагинов вроде Shopkeepers не переносятся (их хранит сам плагин) — замени их магазинами MGP.

## Админ-панель (отдельное окно)
Плагин сам поднимает маленький веб-сервер с панелью управления. Никаких дополнительных программ не нужно.

1. В игре выполни `/mgp panel` (нужно право `mgp.admin`) и нажми на ссылку `[открыть]`. В ссылке уже есть ключ доступа.
   Ключ также лежит в `config.yml` → `panel.token`.
2. Чтобы панель открывалась отдельным окном, нажми в ней кнопку «Открыть в отдельном окне».
   Или установи её как приложение: в Chrome/Edge значок «Установить» в адресной строке. После этого панель живёт в своём окне с иконкой на рабочем столе.

Что можно делать в панели:
* смотреть онлайн, TPS и активные игры, принудительно стартовать или закрывать игры;
* настраивать режимы через формы: игроки и таймеры, голосования, модификаторы, киты, тиры сундуков, торговцы, события по времени, инфо-панель (с предпросмотром цветов), настройки режима;
* настраивать карты: спавны, сундуки, торговцы, триггеры, участки;
* менять общие настройки (хаб, голосование WEIGHTED, сама панель);
* редактировать любой файл целиком на вкладке YAML.

Перед сохранением плагин проверяет конфиг. Если в нём ошибка, файл не сохранится, а панель покажет причину. Сохранённые настройки сразу применяются к новым играм, текущие игры доигрывают со старыми.
Сохранение через формы убирает комментарии внутри разделов. Если комментарии важны, правь файл на вкладке YAML: там он сохраняется как есть.

**Сервер на хостинге.** По умолчанию панель слушает только `127.0.0.1:8765`, то есть доступна лишь с той же машины. Варианты:
* SSH-туннель (самый безопасный): `ssh -L 8765:127.0.0.1:8765 user@сервер`, потом открыть `http://localhost:8765`;
* или `panel.host: 0.0.0.0` плюс открытый порт и `panel.public-url: http://IP:8765`. Тогда ключ — единственная защита, никому не показывай ссылку.

## Что настраивается в `modes/<режим>.yml`
* `min-players`, `max-players`, `countdown`, `fast-countdown` (ускоренный старт при полном лобби), `time-limit`, `max-sessions`.
* `map-vote.type` выбирает тип голосования:
  * `MOST_VOTES`: побеждает вариант с наибольшим числом голосов;
  * `RANDOM_VOTED`: случайный вариант среди тех, за которые голосовали;
  * `WEIGHTED`: каждый голос добавляет шанс (параметры в `config.yml`);
  * `NONE`: случайная карта без голосования.
* `modifiers` задаёт группы модификаторов (время суток, погода, здоровье, эффекты). Режим выбора для каждой группы: `VOTE`, `RANDOM`, `FIXED` или `OFF`.
* `kits`, `default-kit` и `start-items` задают наборы и стартовые предметы.
* Набор проще всего «скачать» из инвентаря: собери предметы, надень броню и введи `/mgp kit save <режим> <id> [команда|all] [название]`. Сохраняются все слоты, броня и вторая рука, предметы целиком (зачарования, имена). При выдаче предметы встают в те же слоты, броня сразу надета. `team` (например `defenders` / `attackers` в осаде) — набор только для этой команды, он заменяет её стандартные предметы. `/mgp kit load|list|delete` — взять себе, список, удалить.
* `loot` содержит тиры сундуков, `trades` — наборы сделок для торговцев.
* **Сундуки и лут.** Лут кладётся только в режимах с `settings.chest-loot: true` (по умолчанию так только у голодных игр). Тир контейнера задаёт предмет-маркер: положи в сундук, бочку, шалкер или любой другой контейнер на карте только железный слиток — будет tier1, только золотой — tier2. Соответствие в `loot-markers` режима. Контейнер с разными предметами маркером не считается. При заполнении маркер исчезает. Если на карте есть хоть один маркер, лут получают только помеченные контейнеры, а список `chests` карты не используется. В режимах без лута сундуки, бочки и шалкеры карты в начале игры пустые (`settings.empty-chests: false` — оставить их содержимое как на карте). Проверить, что видит плагин: `/mgp debug <режим> <карта>`.
* `timeline` — события по времени (пополнение сундуков, сужение барьера, дезматч...).
* `sidebar` задаёт строки инфо-панели справа для каждой фазы, с плейсхолдерами `{time}`, `{alive}`, `{kills}` и другими.
* `time: 6000` — время суток в игре и лобби ожидания стоит на месте (без ключа — как задают модификаторы). Для всех лобби ожидания — `default-lobby.time` в `config.yml` (по умолчанию 6000).
* `settings` — параметры конкретного режима.

### Действия (для timeline, триггеров, модификаторов, китов, win-actions)
`message:`, `broadcast:`, `title: верх | низ`, `actionbar:`, `sound: minecraft:...`, `time: 18000 lock`,
`weather: clear|rain|thunder`, `gamerule: <id> <значение>`, `effect: speed 1 [сек]`, `clear-effects`,
`give: ARROW 16`, `heal`, `max-health: 40`, `border: <размер> [сек]`, `refill-chests [tier]`,
`command: <консольная команда с {player}>`, `mode: deathmatch | pvp-on | pvp-off`.

### Триггеры на карте
Область (`min`/`max`) и режим срабатывания `ONCE`, `PER_PLAYER` или `REPEAT` (каждую секунду, пока игрок внутри).

## Структура кода
```
ru.mgp
├─ MGPPlugin              — точка входа
├─ world/WorldService     — копирование шаблонов, загрузка/выгрузка/удаление миров
├─ config/                — ModeConfig, MapConfig, киты, лут, сделки, модификаторы, таймлайн
├─ vote/                  — голосования и 4 типа подсчёта
├─ session/
│  ├─ GameSession         — состояние одной игры (ожидание → отсчёт → игра → итоги)
│  ├─ SessionManager      — очередь: подбор/создание сессии, общий таймер
│  ├─ ActionRunner        — универсальные действия
│  ├─ HubService          — хаб
│  └─ VisibilityService   — изоляция: видишь и слышишь только свою сессию
├─ logic/                 — режимы: GameLogic (база), HungerGamesLogic, BuildBattleLogic
├─ ui/                    — инфо-панель, GUI-меню, предметы хотбара
├─ panel/                 — веб-сервер и API админ-панели (интерфейс: resources/web)
├─ listener/              — события
└─ command/MgpCommand     — команды и /mgp setup
```

### Как добавить новый режим
1. Создай класс `extends GameLogic` и реализуй `onStart()` и нужные события.
2. Зарегистрируй его в `GameLogics.create(...)` под своим `type`.
3. Создай `modes/<режим>.yml` с этим `type`.
